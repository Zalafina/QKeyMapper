## 目录与文件规则

- 每项任务使用一个稳定的功能子目录，例如 `qkeymapper_mcp_control/`。默认只放 Markdown。
- 每项任务只保留一份主计划，集中记录目标、决策、阶段、估算、进度及最新交接卡片。能力表、验证记录与主计划交叉链接，不另建第二份进度来源。
- 文件名保持稳定，用 Git 历史查看旧版本，不堆放“最终版”、副本、完整聊天或重复模板。
- 单文件建议不超过 256 KiB，单任务目录建议不超过 2 MiB；接近上限时精简重复内容，历史明细由 Git 保存。
- 脚本、维护测试和合成样例放对应源码或测试目录。本目录使用仓库相对链接引用，不复制实现。
- EXE、DLL、PDB、转储、截图、完整日志、构建缓存及个人 INI 不放入本目录；原始证据保留在本机忽略的 `out/`。
- 不提交令牌、凭据、设备身份、私人窗口标题、实际发送文本等敏感内容。需要共享的失败片段先脱敏，并仅保留判断问题所需部分。
- 本机证据索引必须注明来源机器和是否随 Git 同步。另一台 PC 缺少原始证据时，按用例复跑或明确请求必要材料，不将缺失材料描述为已核实。
- 使用仓库相对路径和可传参命令；Qt、MSVC、Python 和仓库根目录可以因机器而不同。个人 Codex 数据库、全局技能及本机缓存不能成为任务恢复的必要条件。
- 任务结束后在原目录标明完成或取消，不复制整个目录作为归档。本页仍只保留导航。

## 进度与验证记录

主计划顶部维护最新交接卡片：阶段与切片 ID、状态、执行机器、源码提交与相关未提交变更、已完成内容、当前验证、未验证项、授权边界、下一步及完成标准、实耗与剩余估算。

状态统一为：未开始／进行中／待验证／受阻／完成。可验证切片结束、重要失败、决策变化及交接前更新。验收未完成时不能把阶段标为完成。

验证记录区分当前检查、历史复用和未执行覆盖，至少包含源码与相关差异、配置、实际 EXE（若运行）、机器／系统、实际桌面（若涉及窗口）、场景、结果和必要证据位置。文档校验不能代替编译或产品验收。

## 双机接续

同一任务同一时间只有一台 PC 写入。优先在同一聊天中连续处理同一计划；换机或会话无法继续时，使用主计划中的状态快照恢复，不复制整段聊天。

### 源 PC

1. 完成或明确暂停当前切片，释放测试输入并正常关闭本轮拥有的测试进程；不关闭用户实例。
2. 更新主计划、能力表及必要验证记录，检查任务差异和未保存材料。
3. 先形成可审阅的本地开发检查点；只有得到明确提交指令后才创建聚焦的本地 commit。
4. 由用户手工 push，并告知接收 PC 要接续的分支及检查点提交。Agent 不自动推送、合并主分支或强制推送。

### 接收 PC

1. 保留本地已有改动，核对任务分支和用户指定的检查点。只允许可快进同步；出现分叉、冲突或不明改动时先核实，不覆盖或重置工作区。
2. 阅读 `AGENTS.md`、本页、主计划顶部卡片及相关能力／验证记录，核对实际 Git 状态与记录是否一致。
3. 探测本机依赖、设备、驱动、桌面和权限；使用当前源码构建需要的目标，不复用另一台机器的构建目录或配对凭据。
4. 完成接续需要的最小检查和当前切片相关用例，再继续卡片中的下一项明确动作；不重复已完成且可复用的工作。
5. 将执行机器和新结果更新到同一主计划。Win10 与 Win11 的系统相关结果分开记录，不互相冒充通过。

意外中断时先检查文件、Git 和保存的进程／操作结果，避免重复执行已发生的副作用。未保存、未提交或未推送的内容不能假定已经同步。交接卡片不是未传输文件的替代品。
