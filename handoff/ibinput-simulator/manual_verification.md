# IbInput 基本功能人工验证

本页只给操作步骤。当前状态、通过范围和剩余任务见[唯一主计划](qkeymapper_ibinputsimulator_integration_plan.md)。使用本次交付的固定提交及独立目录，不覆盖个人配置。

1. 先确认没有其他 QKeyMapper 实例或正在运行的 MCP 输入测试。必要时向 MCP 原线程发送：“请在当前测试安全结束并释放自有输入后，暂缓真实输入测试，等待我完成 IbInput 基本验证；保留现有代码和环境，不制作交接。” 本线程没有代发。
2. 从交付的独立目录启动 QKeyMapper.exe，按正式 manifest 确认 UAC。配置来自同目录 keymapdata.ini；原始样例为 QKeyMapper/tests/ibinput/manual_verification.ini。不要从正式安装目录启动或复制个人 INI。默认不自动开始映射。
3. 确认载入 IbInputBasic 表，四行分别为 F8→右、F9→左、F10→下、F11→上，发送方式 IbInput。单项编辑打开后仍应显示 IbInput；保存后同目录 INI 中 KeyMapData_SendMappingKeyMethod 应为 3#3#3#3。
4. 在“映射设定”打开 IbInput 面板。先手动选择 Logitech G HUB，失败策略保留“不开始映射”；切到自动，再切回手动，保存并重启，确认偏好及四行方式仍保持。被动“刷新状态”不连接驱动；“连接检查”可能激活厂商虚拟设备，但不发送键鼠。没有罗技实体设备并不妨碍使用本次已验证的 G HUB 虚拟通道。驱动登记已观察不等于实际输入已验证，Razer 未知也不等于确认未安装。
5. 关闭会被鼠标误操作的页面，把光标留在安全空白区域，点击“映射开始”。依次短按并释放 F8／F9／F10／F11（每次约0.1～0.2秒），观察对应方向的小幅移动；不要长时间按住。样例速度为1、轮询20ms。释放后应停止移动，界面应显示实际 IbInput 后端。
6. 点击“映射停止”，等清理完成；再次开始／停止一次，确认偏好控件恢复可用、没有持续移动。停止后通过托盘菜单“退出”结束程序，再启动确认方式3及偏好仍保持。窗口右上角关闭可能是收起到托盘，不能据此认定进程已退出。

若只想核对界面／配置，可以不执行第5步；反馈时注明实际范围。出现持续移动、无法停止、释放不完整或启动失败时先停止验证，记录本次窗口状态、使用步骤与同目录日志，不通过反复启动或切换后端掩盖问题。

本检查点产品仅开放 G HUB 相对移动。键盘、按钮及滚轮保留实现，固定客户端的 F24／左键／垂直轮抽查通过，但不等于这些完整产品路径已验收；不要把它们作为本次必须可用的功能。Win10＋GPW、其他版本／后端及重启恢复仍需独立验证。

2026-10-30用户已确认IbInput鼠标指针移动人工验收OK；这里只记录该功能通过，其他能力与界面／配置范围仍按主计划分项验收。

本页用于阶段性基本验证。按主计划R8，先补齐目标功能、完成独立验证及用户完整功能验收，再由用户明确确认合流；届时重新生成新固定SHA的提示词交给MCP原线程。旧运行目录内的MCP_RECEIVE_PROMPT.md仅是历史草案，不因本次鼠标移动通过而直接执行。当前不进入MCP合流；检查点提交／推送仅按用户另行授权执行。


## 两个状态按钮的用法

- **刷新状态**：重新读取厂商安装文件版本、相关进程名和驱动登记。打开面板时自动执行，面板可见时每5秒被动刷新；关闭后停刷。此操作不连接驱动、不发送测试输入，也不代表设备可用或目标应用已收到输入。若外部状态没有改变，列表内容保持相同。手动点击后显示带本地时间的“状态已刷新”，被动刷新只更新采样信息，不覆盖上次操作反馈。
- **连接检查**：映射停止且清理完成后，按全局首选设置尝试建立一次临时连接，随即关闭。可能激活厂商虚拟设备，但不发送键鼠测试输入；成功只能说明这次临时连接成功，不能证明真实映射或目标应用接收。它不是每次开始映射前的必需步骤；真正开始时仍重新连接，停止时释放。
- **当前状态与最近结果**：主窗口“未连接”表示此刻没有活动连接。本轮Popup在连接检查后显示“连接检查通过，临时连接已关闭”或失败结果，和当前未连接分开理解；检查中显示进行提示，偏好及连接按钮暂时禁用。真正映射活动时显示当前后端，停止后回到未连接。失败时查看下方错误，先核对首选设置和厂商软件／驱动状态，不反复点击或自动重启厂商软件。
- **自动和手动**：自动按已配置的候选／能力规则选后端；手动只尝试指定后端。改变偏好后用应用的保存入口保存；关闭面板不自动保存。无法连接时的SendInput回退只在真正开始前生效，不绕过混用／不支持组合，不在运行中切换后端。

## 同表比较两种鼠标移动发送方式

Key2Mouse-Up／Down／Left／Right共用一个合成发送器，同组有效行不能一部分IbInput、一部分其他方式，和原始键是否重复无关。可将八行全部设成同一方式，或每次禁用另一组后启动；也可分成两个普通映射表，停止后切换再开始，且确认附加Common没有引入另一方式。同表普通键盘映射使用SendInput一般不受这条移动组规则限制，但仍须满足其余准入规则。

本轮修订后，移动组混用会同时拦截“保存设定”“保存并映射开始”和单独开始；失败不写入INI、不连接后端。保存时检查本次所保存的各普通表及它们实际附加的Common，禁用／被Common优先规则遮蔽的行不参与；不同普通表彼此独立。软件未安装或暂未连接仍可保存合法配置，其他未开放能力仍按既有运行门控处理。

建议补做一次保存回归：在原四行旁复制四行，原始键改为方向键、方式改为SendInput，分别点“保存设定”和“保存并映射开始”，都应红字拒绝且没有开始映射。将新增四行禁用或统一方式后应可保存，再恢复四行样例继续基本移动验证。不要为了绕过规则手改INI；若要比较方式，分到两个普通表并检查附加Common。
