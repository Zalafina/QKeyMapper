# QKeyMapper 临时缓存

使用本技能处理缓存状态、时长、截止时间、恢复默认及关闭。缓存指令不恢复暂停的开发，也不新增真实输入、驱动或 GUI 授权。技能被加载、用户引用用法或只问格式时，不执行缓存变更。

详细用法、日志字段及可复制的只读复查提示词见[使用与运行复查说明](references/usage.md)。用户要求运行状况复查时先读该说明，只读分析已有记录，不将“复查”转成缓存变更或自动重跑验收。

## 使用入口

显式入口为 `$qkeymapper-gsudo-cache …`；兼容实际送达 Agent 的 `/qkeymapper-gsudo-cache …` 文本和清晰的自然语言请求。不会注册 App 原生斜杠命令；若界面拦截 `/`，使用 `$`。

从仓库根目录用本机已有的普通权限 Python 运行脚本，优先使用 `out/mcp_bridge/venv/Scripts/python.exe`（既定 CPython 3.11.9 x64＋pywin32）。缺少环境时按主计划的环境恢复规则处理，不安装全局包。脚本位置为 `.agents/skills/qkeymapper-gsudo-cache/scripts/cache_control.py`。

```powershell
& out/mcp_bridge/venv/Scripts/python.exe -B -X utf8 .agents/skills/qkeymapper-gsudo-cache/scripts/cache_control.py status
```

把用户请求作为独立参数传给脚本，不拼接为 shell 代码：

| 请求 | 行为 |
|---|---|
| 空参数、status、当前状态、状态 | 只读查询；不存在时明确显示，不创建控制器 |
| 5m、5h、5分钟、5小时、10s | 从现在起重设窗口，可延长或缩短；纯数字按分钟 |
| until 20261025 19:30、直到今天19:30、直到明天0点50份 | 北京时间截止；该位置的份兼容分 |
| restore、恢复默认 | 当前重设为剩余五分钟；不存在时不创建 |
| off、关闭缓存 | 关闭本技能管理的缓存，停止派发新测试，保留既有清理 |
| help、帮助 | 显示示例 |

正整数窗口最长24小时；兼容大小写、空格和全角数字／冒号。不接受过去时间、无穷、零／负值或自动滚到明天；不截断。含义不明确时只问一个短问题，保留当前设置。第一次开启或原缓存失效可能出现 UAC，须用户实际批准；没有确认生效就不能报告已延长。

## 反馈与失败

以脚本实际结果说明：新建了控制器，或复用同一 PID 延长／缩短／重新启用，或恢复默认、关闭、等待审批／失败。给出实际 PID、北京时间旧／新截止时间、剩余时间、当前固定作业和已批准范围。未管理的本机缓存不猜测期限、范围或擅自接管。

只查询状态不会保活或延长窗口。gsudo 的原生 duration 是空闲超时，实际最终限制由控制器单调时钟截止监视完成，到期关闭本 PID 全部缓存；持续执行命令也不延长授权。缩短不假定原生 cache on 覆盖了旧服务。

控制器处理新请求前也核对硬截止；已经到期的旧窗口不能由轮询间隙中的调整请求复活。先确认其关闭，再按用户明确的新请求创建窗口；结果未知仍只查询原请求。失败中的 native_exit_code／requested_window_expired 用于区分原生批准、取消和实际到期，原生exit 0不等于窗口已应用。

长命令使用可返回会话 ID 的工具执行并持续报告进展，不让工具等待阻塞沟通。请求超时会返回 request_id；用 `result <request_id>` 查询保存结果，不重发变更。结果为历史事实，当前有效状态须另查 status；控制器退出／结果淘汰后未知，不假定操作未发生。UAC 取消（999）不自动重试或替用户批准。

## 让后续测试复用该控制器

优先读[公共测试接入与完整示例](references/test-actions.md)。新测试先判断是否确实需要管理员：普通 Qt 维护、开发、SDK主体、桥接、采样和截图继续普通权限。必要的原生目标启动／关闭和固定GUI助手才走受管控制器；不要先另开临时缓存。

`scripts/test_process.ps1` 的 `Start-QkmTestProcess -UseGsudo`／`Close-QkmTestProcess` 已接入；Python使用 `scripts/managed_test.py` 的 `perform`。SDK高权限夹具及Product固定GUI动作也走此入口。实际gsudo由缓存所属普通控制器派发；传PID或环境变量不能代替该调用链。

新控制器默认范围为空。Agent按已经批准的作业检查原生EXE的构建来源、内容身份、精确参数／环境、桌面、输出、固定助手代码及清理预算，生成结构化定义；另在 `authorize` 的 `test_actions.definitions` 登记完整定义SHA-256，再 `register --definition-file`。元数据不能自授权。只按路径／文件名信任目标、把Python／PowerShell／cmd等解释器登记为任意脚本启动器、任意命令／Qt属性均不允许。

同一目标增加普通用例只更新cases；同类新目标另登记定义，不改缓存核心。不因新文件名／case ID重问已批准的范围；真正新增输入、驱动、GUI或其他系统副作用仍先说明并获得所需授权。固定GUI动作沿用已有受限助手；新增动作在该助手实现并独立验证，定义绑定实际助手摘要。无自有进程时可重新审核登记助手更新，不重启控制器。

内部接口：

- `authorize --scope-file <JSON>`：完整替换范围，保留已有允许项。旧product／source／input_regression／identity_probe范围仍有效；test_actions须有reason及最多32个定义摘要。
- `register --definition-file <JSON>`：登记已获独立范围许可的目标／用例。字段及示例见引用页；活跃目标不能被覆盖。
- `test-action --action-file <JSON>`：仅Start／Close／Gui三类结构化动作。关闭及GUI核对本控制器拥有的PID、创建时间、EXE和桌面；PID复用拒绝。
- `run --job-file <JSON>`：保留整套product／source／input_regression和固定身份探针。控制器从这些既定参数生成受限定义；普通子脚本不加旧的 `--gsudo-cache`。该旧选项现在明确拒绝，不再创建嵌套／临时缓存。
- `result <request_id>`：查询原结果。超时／结果未知不得通过新ID盲目重放。

整套run占用期间，控制器继续串行处理该作业的内部公共请求。临时作业令牌仅区分归属，调用方还要核对实际Medium／登录身份；它不是授权凭据或缓存继承机制。无关请求返回busy，不另建控制器。

登记不延长期限。启动前预留整个用例及清理预算；到清理保留时间尝试关闭自有目标。off先停止新测试并在原硬截止内清理；已到期、缓存丢失或身份无法核实时不擅自提权／强杀，报告遗留及结果未知。活动目标不能把窗口缩到不足20秒；可先off完成清理，再设置更短窗口。

旧控制器首次升级须空闲且无自有进程：运行 `upgrade`，核实旧缓存关闭，再以原截止及剩余上限启动新版，可能需要一次UAC。不静默重算时长；失败保留原请求ID及旧截止，先查明原因，未经确认不重试。升级不迁移进程拥有关系，定义需重新登记。

专门验证UAC提示／拒绝必须使用独立、无继承缓存的普通调用链，公共助手显式 `-UncachedGsudo`；若实际仍有缓存则拒绝，不全局清除。首次开启、失效恢复、系统独立RunAs／安装器等入口及原生服务在检查后的异常失效仍可能要求审批，不承诺所有UAC免审批。入口未登记或缓存缺失明确报因，不默认回退直接gsudo。

身份探针及accept_cache.py仍按既有固定边界使用；source_cleanup须已有私有桌面源测试授权，不能从时长命令推导。真实输入不因run或登记而自动获得许可。

## 生命周期与交接

每工作区／当前用户登录只允许一个受管普通控制器。核对实际 PID、创建时间、解释器和 Medium 权限；不按进程名或旧 PID 猜测。运行记录、通信和日志在忽略的 `out/gsudo_cache/`，不随 Git 或跨 PC 继承；技能和测试源码随 Git。

任务正式结束或用户要求关闭时执行 off，并确认 closed／缓存不可用；普通消息、Fast 切换或短暂停顿不擅自重启、延长缓存。到期不再派发新测试；活动测试仍按既有逻辑清理，异常清理可能需要用户 UAC，不能谎报已清理或强杀用户实例。首次创建、缓存失效和异常恢复不能保证无需 UAC。

更新进度／验收到本任务唯一主计划，不在技能内维护任务进度。MCP 主计划入口：`handoff/qkeymapper_mcp_control/qkeymapper_mcp_automation_plan_codex.md`，缓存边界见 CACHE-40。不要恢复 `out` 中已经结束的旧临时控制器，不修改全局 CacheMode／CacheDuration，不使用 PID 0、无限期或全局 -k。

环境及覆盖按实际OS／gsudo／Python版本分别记录，证据和未验边界见 `handoff/qkeymapper_mcp_control/gsudo_cache_pending_validation.md`。换PC或gsudo版本变化后先核对依赖和身份，再按下述日常观察策略使用与复查；不沿用另一PC的PID或把模拟／短测当作真实休眠及长期验收。

## 日常记录与复查

受管控制器自动向本机 `out/gsudo_cache/history/events-YYYYMMDD-NNNN.jsonl` 追加精简历史：关键请求／结果、窗口和任务变化、关闭核实，以及最多每60秒一次的自身存活／资源摘要。心跳不调用gsudo、不执行提权探针、不续期；cache_available必须连同native_checked_at理解，旧观测不是当前事实。正常status不逐条写历史，无控制器的查询也不创建记录进程。

记录采用字段白名单，不写凭据、SID／用户名、完整私人路径、配置／映射、完整命令或授权reason。每文件约1 MiB，写入时按30天／总20 MiB先到上限轮转，只清理自身摘要文件；原有原生／任务日志不受此轮转管理。

日志失败不改变缓存操作结果或阻止清理；status／closed中的history描述最近写入和missed_events，恢复写入不抹去缺口。发现记录失败时说明诊断不完整，不谎报缓存操作失败或自动重建缓存。没有结尾、日志轮转、损坏行及只有心跳都不能证明此前任务／清理成功。

其他PC／长时／自然休眠改为日常使用中积累证据后复查，不单独等待凑样本。只有异常或关键证据不足影响使用时补最小必要测试，不要求每次换机完整复跑。结论只覆盖实际发生的系统、代码版本、会话和窗口；不恢复暂停的MCP开发。
